## 2　bug 的真因與修法

**症狀**：貼 `⿰木⿳金⿰水火土`，五個葉全部疊在一起，糊成一大塊 ✗。

**真因**：頁面裡有一份**自己寫的分框**（`pinxing-page.js` 的 `idsComposeNaive`），
它是第 126 輪的舊版——把每個部件用 **200×200、不縮放**擺在自己的格**心** ✗。
部件遠大於格子，於是每一塊都大幅溢出、互相壓上去 ✗。

**正解**：分框模塊 `tools/ids-glyph.ts` 的 `idsGlyph(ids, lib)` 會**等比縮進自己那一格** ✓——
例如 `⿰木⿳金⿰水火土` 的框是：

| 葉 | 框 |
| --- | --- |
| 木 | `[0, 0, 100, 200]` |
| 金 | `[100, 0, 200, 67]` |
| 水 | `[100, 67, 150, 133]` |
| 火 | `[150, 67, 200, 133]` |
| 土 | `[100, 133, 200, 200]` |

**兄弟框不重疊** ✓＝筆劃不會交錯 ✓。

**修法**：`idsComposeNaive()` 改成一行包裝：

```js
function idsComposeNaive(ids) {
  var r = null;
  try { r = idsGlyph(String(ids), LIB); } catch (e) { return null; }
  if (!r || !r.ok) return null;
  return { lib: r.lib, idx: r.idx, n: r.n, problems: r.problems || [], slots: r.slots };
}
```

⚠ **不要再自己抄一份分框** ✗：文件上早寫著「頁面的 `idsComposeNaive` 只剩包裝」，
但那一輪（第 129 輪）的修改**沒有進版控**，被還原之後就變回舊實作 ✓。

**驗證**：`out/fix-ids-shot.png`（修好的排版）、`out/fix-ids-wand.png`（按了魔棒之後）。
出圖的一次性探針是 `out/_fixshot.ts`（`out/` 不入版控）：

```powershell

bun run out/_fixshot.ts "⿰木⿳金⿰水火土" out/fix-ids-wand.png 460 560 wand
```

## 4　失去的進展與版控處置（**這一節最重要**）

**現象**：重裝／重啟之後，頁面回到舊版：
① 分框不分縮（糊成一塊）✗；② 魔術棒不見了 ✗。
但 `git status` 卻是乾淨的 ✗。

**原因**：`.md` 每一輪都有 commit ✓，但 `tools/` 的修改**長期沒有 commit** ✗。
工作區被還原到上一次 commit（`1628f06 crash backup`）時，**未提交的程式改動整批消失** ✗——
而 `git status` 當然是乾淨的（它只看得見「相對於 commit」的差異 ✓）。

**找過但沒有備份**：整包專案、git 的 dangling objects（只有兩個 md blob 與一個重複 commit）、
`out/` 的舊 html 都沒有可還原的版本 ✗。魔棒與模塊整合是**照文件規格重建**的 ✓。

**處置**：
1. 本輪已把 3 個工具檔**一起 commit** ✓。
2. 建議：**每輪收工就把 `tools/` 的改動 commit**（或至少一天一次）——
   不要再讓「重要到值得寫進文件」的程式改動只活在硬碟上 ✗。
3. ⚠ `../README.md` 的「版控範圍」寫著「只追蹤兩個位置的 `.md`」，
   但 `git ls-files` 顯示 `tools/` **早就被追蹤** ✓——以實況為準；
   這條規則要不要改寫，等師父裁定 ✗。
