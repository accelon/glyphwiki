## 2　bug 的真因與修法

**症狀**：貼 `⿰木⿳金⿰水火土`，五個葉全部疊在一起，糊成一大塊 ✗。

**真因**：頁面裡有一份**自己寫的分框**（`pinxing-page.js` 的 `idsComposeNaive`），
它是第 126 輪的舊版——把每個部件用 **200×200、不縮放**擺在自己的格**心** ✗。
部件遠大於格子，於是每一塊都大幅溢出、互相壓上去 ✗。

**正解**：分框模塊 `tools/ids-glyph.ts` 的 `idsGlyph(ids, lib)` 會**等比縮進自己那一格** ✓——
例如 `⿰木⿳金⿰水火土` 的框是：

| 葉 | 框 |
| --- | --- |
| 木 | `[0, 0, 100, 200]` |
| 金 | `[100, 0, 200, 67]` |
| 水 | `[100, 67, 150, 133]` |
| 火 | `[150, 67, 200, 133]` |
| 土 | `[100, 133, 200, 200]` |

**兄弟框不重疊** ✓＝筆劃不會交錯 ✓。

**修法**：`idsComposeNaive()` 改成一行包裝：

```js
function idsComposeNaive(ids) {
  var r = null;
  try { r = idsGlyph(String(ids), LIB); } catch (e) { return null; }
  if (!r || !r.ok) return null;
  return { lib: r.lib, idx: r.idx, n: r.n, problems: r.problems || [], slots: r.slots };
}
```

⚠ **不要再自己抄一份分框** ✗：文件上早寫著「頁面的 `idsComposeNaive` 只剩包裝」，
但那一輪（第 129 輪）的修改**沒有進版控**，被還原之後就變回舊實作 ✓。

**驗證**：`out/fix-ids-shot.png`（修好的排版）、`out/fix-ids-wand.png`（按了魔棒之後）。
出圖的一次性探針是 `out/_fixshot.ts`（`out/` 不入版控）：


## 3.5　字框「孫」（第三態，2026-10-15 師父的需求）

* 字框鈕：**緊 → 孫 → 無**（**三態**循環 ✓；「原」已與「緊」**合併** ✓，localStorage 也接受 `deep` ✓）。
* **框＝能包住那個部件所有筆劃的最小框** ✓，而且**直接問引擎** ✓：
  直屬部件用 `compose-fit.ts` 的 `inkOfRefInParent()`（含 `stretch` 的真實落點 ✓）、
  更深層的孫用 `inkOfPathInRoot()`（把整條引用鏈做成合成字形再量 ✓）。
  ⚠ 自己用仿射 `projectBox()` 推的只在比例剛好相符時才對 ✗
  （`邏` 的 `羅`：仿射 [47,14,197,164] vs 引擎 [56,13,188,173] ✗）。
* 「孫」＝**所有子孫**的最小框，直到**獨體部件** ✓；深層框畫**虛線**、**帶 `data-box`**、與部件格互相連動 ✓。
* **停止條件＝`comp` 表說它不是合字** ✓（＝獨體 ✓）；**往下一層要用實際的 KAGE 引用** ✓
  （`refSlotsOf()`）——**不要**用 `componentBoxesShallow()` ✗：它會拿 `comp` 表重新配對，
  拼形換掉的引用（例 `寶缶支` 的 `缶 → 支`）會被它改名回去 ✗（框數與名字都不對 ✗，師父抓到 ✓）。
* **部件清單（2026-10-15 師父的回報）**：
  ① **孫模式**：清單＝**所有子孫**（`renderBoxChips(deepBoxesOfMain())`），點框 ↔ 點格子互相亮起、
     滑過框那格也亮（`hoverChip()`）、**滑過格子大字的框也亮**（`hoverFrame()`）；
     ⚠ 孫框的 `.cbox.sub` 要用**另一份** `:hover`／`.on`／`.hover` 才蓋得回來 ✗。
  ② **構字式（IDS）**：清單＝**構字式的那幾塊**（`MAIN.boxes`；以前整段清空 ✗）。
  兩者的格子都**只看得到、不能換**；點一下＝選它 ✓。
  ③ **排版緊湊**（師父 2026-10-15）：部件清單改成**自動換行、吃滿大字右邊的寬度**（`.side` 加 `flex:1 1 56px`、
     `.chips` 加 `flex-wrap:wrap; width:100%`）——原本是豎排單欄，右邊一大片空著 ✗。
* **部件清單的主角選擇與排版**（2026-10-15 師父回報）：
  ① **被改掉的字不能當主角**——序列的 `eval.log`（「X 的 Y → Z」）裡的 X 與 Y 都不在最後字形裡，
     要跳過（否則 `峰夆電雨水` 列 `電`、`髜昇厏乍电` 列 `厏` ✗）；沒有合格主角時列**拼出來的形**的部件，
     而被拼形改過的引用（fork 同索引、筆劃不同）要改列它**實際畫的引用**（`composedChips()` ✓）。
  ② **排版順序**：大字 → 部件清單 → 建議並排（`order` ✓；否則建議並排會把部件清單擠到大字下方 ✗）；
     寬螢幕把卡片放寬到 720px（`@media (min-width:760px)`），三者並排 ✓。
* ⚠ 已知：若某個字的 IDS 分量與 KAGE 引用**配錯**（例 `想` 的 IDS `相` 配到 KAGE 的 `目` 格），
  孫框會**沿著路徑實際走到的引用**（`refAtPath()`）畫 ✓——所以 `想` 的孫框只有 2 個（目、心 ✓），

## 4　失去的進展與版控處置（**這一節最重要**）

**現象**：重裝／重啟之後，頁面回到舊版：
① 分框不分縮（糊成一塊）✗；② 魔術棒不見了 ✗。
但 `git status` 卻是乾淨的 ✗。

**原因**：`.md` 每一輪都有 commit ✓，但 `tools/` 的修改**長期沒有 commit** ✗。
工作區被還原到上一次 commit（`1628f06 crash backup`）時，**未提交的程式改動整批消失** ✗——
而 `git status` 當然是乾淨的（它只看得見「相對於 commit」的差異 ✓）。

**找過但沒有備份**：整包專案、git 的 dangling objects（只有兩個 md blob 與一個重複 commit）、
`out/` 的舊 html 都沒有可還原的版本 ✗。魔棒與模塊整合是**照文件規格重建**的 ✓。

**處置**：
1. 本輪已把 3 個工具檔**一起 commit** ✓。
2. 建議：**每輪收工就把 `tools/` 的改動 commit**（或至少一天一次）——
   不要再讓「重要到值得寫進文件」的程式改動只活在硬碟上 ✗。
3. ⚠ `../README.md` 的「版控範圍」寫著「只追蹤兩個位置的 `.md`」，
   但 `git ls-files` 顯示 `tools/` **早就被追蹤** ✓——以實況為準；
   這條規則要不要改寫，等師父裁定 ✗。
