## 1. MVP 現在長什麼樣

`out/kage-viewer.html`（1.31 MB 離線單頁）三段：

1. **內嵌組字編輯器**：textarea 輸入含 `︵︶` 的文字，下面即時預覽。
   正常文字用系統字形，只有構形序列被換成內嵌 SVG。可調字級／字體／顏色，
   可切兩種讀法，可開關重疊警示。IME 組字中自動停用裝飾（施工單 §四 缺口四）。
2. **開始組字**：光標左邊的字 → 列出可替換部件（字形預覽按鈕，含層級）。
3. **字形檢視**：原本的整格預覽（每字 200px 看細節）。

## 2. V1：內嵌 SVG 的顏色／大小／基線

### 2.1 顏色與大小照施工單，沒問題

`fill: currentColor` ＋ `width: 1em; height: 1em` 照原樣，實測會跟隨旁邊的字
（換色、改字級、深淺主題都跟著走）。

### 2.2 基線：施工單的 `-0.1em` 要改成 `-0.22em`

量測方法（`out/v1-baseline-report.html`）：把系統字與內嵌 SVG 放在**同一行正常的
inline flow** 裡（字級 100px），逐列比較「SVG 墨跡下界」與「系統字墨跡下界」，
Δ = 0 就是同基線。

| `vertical-align` | 0.10 | 0.15 | 0.20 | **0.22** | 0.25 | 0.30 |
| --- | --- | --- | --- | --- | --- | --- |
| Δ（px，100px 字級） | −12 | −7 | −2 | **0** | +3 | +8 |

> **方法論的坑（花了我三輪）**：不能把 SVG 用 `position: absolute` 定位去量。
> 絕對定位不參與基線對齊，量出來的位移完全不同（我先得到 −0.38em 這個錯答案）。
> 一定要在真正的 inline flow 裡量。

### 2.3 護欄有效

`︵街行︶`（太短）、未成對的 `︵街圭日`、跨行的序列，全部原樣顯示純文字，
一個字都沒被吃掉（有一條斷言：掃描結果可完整還原原文）。

## 3. V2：語意與示範素材

語意照 `../format.md`「進階任務 2」：**`基字 ＋ 舊部件 ＋ 新內容…`，新內容可再遞歸**。

```
峰夆電雨水 ＝ 峰 的 夆 →（電 的 雨 → 水）      ← 實測正確，兩層都對
```

### 3.1 示範素材改用引擎做得好的例子

師父指示「不一定要用我給的例子，引擎有瑕疵先略過」。所以我先掃過候選、
再篩出**沿用原框、100% 不縮**的替換——那些才是引擎表現最好的情況：

```
街圭日　街圭月　街圭山　街行月　街行土
寶貝口　寶貝山　清青日　清青月　城土日　地也日　地也山
盟明月　盟明口　峰山日　峰夆水　字宀口　字宀山　字宀大　話舌日
```

這 20 個全部 `scale = 100%`（沿用原框），做出來的字乾淨、在句子裡讀得順。
頁面範例文字與 `out/demo-cases.html` 都用這一批。

### 3.2 為什麼前三種「自動評分」都失敗（給下一版避坑）

想把「好不好看」自動化，試了三種啟發式，**全部不成立**：

| 啟發式 | 為什麼失敗 |
| --- | --- |
| 長寬比 | CJK 部件幾乎都是滿格：日 0.76、木 0.99、水 1.02、十 1.00 → 分不出好壞 |
| 多邊形周長 | 滿格部件周長幾乎一樣 → 全部得到 1.00 |
| 墨跡覆蓋率 | `風` 是 0.22、`日` 是 0.80，差的是**筆畫粗細與字的密度**，不是好壞 |

**唯一可靠的客觀訊號是 `composeFit` 回報的 `scale`**（要不要縮、縮多少）。
所以我把 `composeFit` 改成會回報每個替換步驟的 `scale` / `arDiff` / `overflow`，
並在 UI 上直接標出來（見 §4）。

## 4. 引擎瑕疵：量化、列表、在 UI 上標紅（MVP 不修）

「行舞不好看」的量化版本就是 **`scale` 很小**——部件放不進原槽位，被等比縮小：

| 序列 | scale |  |
| --- | --- | --- |
| 街圭舞 | 46% | 舞 被硬塞進 圭 的槽位 |
| 漢氵月 | 68% | 月 塞不進 氵 的窄槽位 |
| 明日月 | 74% |  |
| 城土月 | 76% |  |
| 寶貝林 | 93% |  |

MVP 的處理（不修引擎，但**不讓使用者被騙**）：

1. **預覽區**：被縮小（scale < 90%）的序列加紅色虛線底線，滑上去顯示實際縮放倍率。
2. **部件按鈕**：每個 L1 部件標出「換上候選部件時最好的縮放」，
   < 90% 的按鈕標紅——**使用者一眼就知道哪個部件換上去會難看**。
3. **品質把關**：另外還在量跨部件筆劃最短距離，但**比增量不比絕對值**
   （`寶` 自己的基線就是 0.7，已知良好的 `寶缶支` 也是 0.7；拿絕對門檻會誤殺好結果）。

`scale` 的判準寫在 `tools/compose-fit.ts` 的 `FitStep`，量測依據寫在
`tools/case-sheets.ts` 的檔頭註解。

## 5. 資料層的兩個發現（建議記進下一版前提）

1. **「可替換部件」比施工單預期的少**。施工單 §四 寫「街 → 行彳亍圭土」，
   實測只有 **`行`、`圭`（L1）與 `彳`（L2）**：`亍` 與 `土` 在 KAGE 裡
   **已被展開成筆畫，不是獨立的引用節點**，所以換不掉。
   要能換得做「整棵子樹重畫」（可行性研究 §2.1 也點到這個方向），不在 MVP 範圍。
2. **`listReplaceables` 會收到指向 base 自己的引用**（樹裡有回去的引用），
   要排除，否則會出現 `街街日` 這種自己換自己的荒謬序列。已在 `evalSeq` 與
   `tools/case-sheets.ts` 兩處處理。

### 附註：一個未定案的語意分歧（不阻塞 MVP）

`彳舞亍` 單獨出現時有兩種讀法：**遞歸**（彳 的 舞 → 亍，但 彳 裡沒有 舞 → 失敗）
或**串接**（⿲彳舞亍，三件並排）。預設是「遞歸優先，讀不成才串接」，
UI 上有下拉選單可切「嚴格遞歸」。官方例子（`峰夆電雨水`）只有預設讀法能跑。
這一條不影響 MVP（示範素材已改用無歧義的例子），但有需要時可以定案。
